# Phase 6: CI (GitHub Actions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a GitHub Actions workflow to each repo (`technet-server`, `technet-react-redux`) that runs the existing test suite (and lint, client-side only) on every push/PR to `main`.

**Architecture:** Two independent, single-job workflow files — no shared logic, no reusable composite action, since each repo's CI need is a 3-4 line job. Each workflow: checkout, Node 20 setup with npm cache, `npm ci`, then the repo's existing scripts (`npm test` for server; `npm run lint && npm test` for client).

**Tech Stack:** GitHub Actions (`actions/checkout@v4`, `actions/setup-node@v4`), each repo's existing npm scripts (no new tooling).

## Global Constraints

- One PR per repo, per the established workflow (commit → push → PR → merge).
- No lint step for `technet-server` — no ESLint config exists there, and adding one was explicitly declined during Phase 6 brainstorming.
- No `build` step for `technet-react-redux` — scope is lint+test only, matching the roadmap's original wording.
- Node version: `'20'` in both workflows (neither repo declares an `engines` field; 20 is a free, safe choice).
- No secrets/env vars needed in either workflow — server's test uses `mongodb-memory-server`, client's test has no network dependency.
- A workflow file's real verification is a live Actions run against a real PR — YAML syntax can be checked locally, but "does this actually pass in GitHub Actions" can only be confirmed once pushed.

### Task 1: Server CI workflow

**Files:**
- Create: `.github/workflows/ci.yml` (in `technet-server`)

**Interfaces:**
- Produces: a workflow named "CI" that runs `npm test` on push/PR to `main`. No other task depends on this file's contents.

- [ ] **Step 1: Create the workflow file**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm test
```

- [ ] **Step 2: Validate YAML syntax locally**

Run: `python3 -c "import yaml, sys; yaml.safe_load(open('.github/workflows/ci.yml'))" && echo "valid YAML"`
Expected: `valid YAML` (no exception). This only confirms syntax, not that the workflow actually passes on GitHub — that's confirmed later when the PR is opened and Actions runs for real.

- [ ] **Step 3: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add GitHub Actions workflow to run tests on push/PR"
```

### Task 2: Client CI workflow

**Files:**
- Create: `.github/workflows/ci.yml` (in `technet-react-redux`)

**Interfaces:**
- Produces: a workflow named "CI" that runs `npm run lint` then `npm test` on push/PR to `main`. Independent of Task 1 (different repo, no shared state).

- [ ] **Step 1: Create the workflow file**

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      - run: npm ci
      - run: npm run lint
      - run: npm test
```

- [ ] **Step 2: Validate YAML syntax locally**

Run: `python3 -c "import yaml, sys; yaml.safe_load(open('.github/workflows/ci.yml'))" && echo "valid YAML"`
Expected: `valid YAML`.

- [ ] **Step 3: Sanity-check the lint step won't fail on current code**

Run: `npm run lint`
Expected: exits 0 (no errors) against the current codebase, since CI will run this exact command. If it fails, that's a pre-existing lint issue this task should NOT silently fix (out of scope) — report it as a concern instead of papering over it, since fixing unrelated lint debt isn't part of "add a CI workflow."

- [ ] **Step 4: Commit**

```bash
git add .github/workflows/ci.yml
git commit -m "ci: add GitHub Actions workflow to run lint and tests on push/PR"
```
